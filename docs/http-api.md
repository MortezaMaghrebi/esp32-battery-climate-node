# ClimateLink HTTP API v1

The same bearer token authorizes ingestion and dashboard reads in this prototype. Set CLIMATE_API_TOKEN to 16–128 URL-safe ASCII characters. Use HTTPS for public deployment. The bundled stdlib HTTP server is intended for development or a controlled installation behind a reverse proxy; add deployment access controls, rate limits and per-device token ownership before an Internet rollout.

## POST /api/v1/measurements

Headers: `Content-Type: application/json`, `Authorization: Bearer <token>` and Content-Length. Maximum request body 16384 bytes, 1–32 samples. Chunked requests are not supported.

```json
{
  "schema_version": 1,
  "device_id": "CL-AABBCCDDEEFF",
  "session_id": "1234abcd",
  "firmware": "0.1.0",
  "simulated": true,
  "battery_mv": null,
  "dropped_samples": 0,
  "samples": [
    {"sequence": 1, "timestamp": null, "temperature_c": 23.1, "humidity_pct": 45.2}
  ]
}
```

device_id is CL- plus twelve uppercase hexadecimal MAC characters. session_id is eight lowercase hex characters generated on cold boot and retained over deep sleep. sequence increases per wake within a session. timestamp is Unix seconds UTC or null when the device clock was not synchronized. received_at is independently generated by the server in UTC. Dummy telemetry must remain simulated=true. Battery is null until a real measurement circuit exists.

Response after SQLite commit: HTTP 202, `{"ok":true,"accepted":1,"inserted":1,"duplicates":0}`. Uniqueness is `(device_id, session_id, sequence)`. Repeating an identical batch yields inserted=0 and duplicates equal to batch length. The server ignores already-stored keys; they are not updated. Validating the entire batch precedes any inserts.

The device treats any 2xx as success. Server and reverse proxy must only send 2xx on successful durable acceptance. HTTP 400 is invalid JSON/schema/data, 401 missing/invalid bearer, 411 missing length, 413 body too large, 415 incorrect content type and 503 database failure. Firmware retains its buffer after non-2xx or transport failure and retries at the next configured upload boundary. The receiver is deduplicating, since a response can be lost after a successful commit.

## GET endpoints

- `/health`: public liveness and schema version; no measurements.
- `/api/v1/devices`: bearer required; latest sample and cumulative sample_count per device.
- `/api/v1/measurements?device_id=CL-AABBCCDDEEFF&limit=120`: bearer required, limit 1–500. Returned samples are oldest-to-newest within the most recently received subset. Ordering uses server insertion order; timestamps may be null.
- `/`: public dashboard shell. Its JavaScript calls the same protected GET APIs. No data is included in the public HTML. The token remains in page memory and is cleared on logout/reload; no localStorage, cookies or third-party resources are used.

The local prototype retains all received samples. There is no automated retention policy, account system, device deletion UI or multi-tenant isolation.
