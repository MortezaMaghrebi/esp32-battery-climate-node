# ClimateLink

نسخه اولیه پایش محیط با ESP32-WROOM-32UE، اپ اندروید و سرور مستقل.
در این نسخه **تمام مقادیر دما و رطوبت شبیه‌سازی شده‌اند**؛ اندازه‌گیری باتری وجود ندارد و مقدار آن `null` است.

## اجزای پروژه

- `climate_link_firmware`: پروژه ESP-IDF برای هدف `esp32`، NimBLE، تنظیم Wi-Fi از طریق BLE، ارسال JSON و Deep Sleep.
- `climate_link_android`: اپ Java با نام ClimateLink، همان package اولیه `com.codestoon.climatelink` و تنظیمات Gradle پروژه شما.
- `climate_link_hardware`: فایل‌های اصلی Altium؛ نرم‌افزار بر اساس برد IOT V1.5 تنظیم شده است.
- `climate_link_server`: سرور Python و SQLite، API و داشبورد وب فارسی؛ بدون وابستگی pip.
- `docs`: قرارداد ارتباط و محدودیت‌های نسخه اولیه.

## راه‌اندازی سرور محلی

Python 3.11 یا جدیدتر لازم است. در PowerShell:

```powershell
cd D:\Github\esp32-battery-climate-node\climate_link_server
$env:CLIMATE_API_TOKEN = (python -c "import secrets; print(secrets.token_urlsafe(32))")
Write-Output $env:CLIMATE_API_TOKEN
python server.py --host 0.0.0.0 --port 8080
```

توکن چاپ‌شده را برای اپ و داشبورد نگه دارید. برای استفاده‌های بعد، همان مقدار را در متغیر محیطی قرار دهید؛ اجرای مجدد فرمان تولید توکن، مقدار جدیدی می‌سازد.
اگر متغیر محیطی تنظیم نشده باشد، سرور توکن موقت جدیدی می‌سازد و در کنسول نشان می‌دهد. فایل `.env` به صورت خودکار خوانده نمی‌شود.

داشبورد روی [localhost:8080](http://localhost:8080) است. آدرس IPv4 کامپیوتر را با `ipconfig` پیدا کنید؛ مثلاً در اپ بنویسید:

```text
http://192.168.1.10:8080/api/v1/measurements
```

گوشی، برد و کامپیوتر را به شبکه محلی متصل کنید. برای دسترسی برد، مجوز شبکه خصوصی Windows Firewall ممکن است لازم باشد.
در اپ، گزینه «اجازه HTTP ... فقط برای آزمایش» را برای این آدرس فعال کنید؛ HTTP توکن و داده را رمزنگاری نمی‌کند.
برای نصب عمومی، سرور را پشت reverse proxy با HTTPS و گواهی معتبر عمومی اجرا کنید؛ در اپ آدرس `https://.../api/v1/measurements` را بدهید و گزینه HTTP را خاموش کنید.
سرور اولیه یک توکن مشترک برای دستگاه‌ها و داشبورد دارد؛ چندکاربری، ثبت‌نام و مدیریت توکن اختصاصی هر دستگاه هنوز پیاده نشده است.

داده‌ها در `climate_link_server/data/climate.sqlite3` نگهداری می‌شوند. داشبورد دستگاه‌ها، نمودار دما و رطوبت، آخرین دریافت و ۱۲۰ نمونه اخیر را نمایش می‌دهد.

## امتحان داشبورد بدون برد

در یک ترمینال دیگر، توکن همان سرور را تنظیم و نمونه آزمایشی ارسال کنید:

```powershell
cd D:\Github\esp32-battery-climate-node\climate_link_server
$env:CLIMATE_API_TOKEN = 'توکن-چاپ-شده-سرور'
python send_demo.py
```

این فرمان ۲۰ نمونه با شناسه `CL-000000000001` و برچسب شبیه‌سازی‌شده به سرور می‌فرستد.

## ساخت firmware و پروگرام

محیط رسمی **ESP-IDF 5.5.6** را نصب کنید و فرمان‌ها را در ESP-IDF PowerShell اجرا کنید:

```powershell
cd D:\Github\esp32-battery-climate-node\climate_link_firmware
idf.py set-target esp32
idf.py build
idf.py -p COM5 flash monitor
```

`COM5` را با پورت واقعی برد عوض کنید. هدف این ماژول **esp32** است؛ اسم قدیمی `ESP32-S3.SchDoc` نشانه S3 بودن ماژول نیست.
بردهای مونتاژ قدیمی باید اصلاح R40 و R41، مقاومت‌های ۱۰ کیلو pull-up روی EN و IO0، مطابق یادداشت سخت‌افزار داشته باشند.
اگر مدار auto-reset وجود ندارد، هنگام پروگرام IO0 را پایین نگه دارید و EN را ریست کنید؛ برای اجرای عادی IO0 باید آزاد/بالا باشد.

## راه‌اندازی اپ

پوشه `climate_link_android` را در Android Studio باز کنید و Gradle Sync انجام دهید.
نسخه‌های AGP، Gradle و SDK اولیه پروژه حفظ شده‌اند؛ minSdk برابر ۲۴ است.
رابط بومی Material 3 شامل سه صفحه نمای کلی، دستگاه‌ها و تنظیمات است و از فونت فارسی وزیرمتن، آیکن‌های برداری و چیدمان راست‌به‌چپ استفاده می‌کند. مجوز فونت در پوشه licenses و داخل APK قرار دارد.
طراحی جدید با اسکیل [Taste](https://github.com/Leonxlnx/taste-skill) از سطح‌های مشکی، نوشته‌های پلاتینی و رنگ شامپاینی محدود برای داده‌ها استفاده می‌کند و همیشه تیره است. نشان اختصاصی چرخهٔ بیداری، اندازه‌گیری، ارسال و خواب در رابط و آیکن برنامه استفاده شده است.
خطاهای کنار ورودی، گزینه‌های پیشرفته جمع‌شونده، جلوگیری از شروع چرخه با تغییرات ذخیره‌نشده و انطباق با فونت بزرگ حفظ شده‌اند. مقادیر ناموجود با خط تیره نمایش داده می‌شوند و داده‌های شبیه‌سازی‌شده برچسب دارند.
[نمای کلی](docs/screenshots/taste/overview.png) · [دستگاه‌ها](docs/screenshots/taste/devices.png) · [تنظیمات](docs/screenshots/taste/settings.png) · [سیستم طراحی و اعتبارسنجی](design-system/climatelink/MASTER.md)

```powershell
cd D:\Github\esp32-battery-climate-node\climate_link_android
.\gradlew.bat :app:assembleDebug :app:lintDebug
```

APK در `app/build/outputs/apk/debug/app-debug.apk` ساخته می‌شود.

۱. برد را روشن/ریست کنید. در Serial Monitor نام دستگاه و **PIN شش‌رقمی** آن چاپ می‌شود.
۲. در اپ جست‌وجو کنید و دستگاه `ClimateLink-xxxxxx` را انتخاب کنید.
۳. مجوز Nearby devices را بدهید و PIN را در پنجره استاندارد اندروید وارد کنید. در اندروید ۱۱ و قدیمی‌تر، مجوز و سرویس Location هم برای اسکن BLE لازم است.
۴. نام Wi-Fi **۲٫۴ گیگاهرتز**، رمز، آدرس endpoint، توکن، فاصله نمونه‌برداری و تعداد نمونه در هر ارسال را وارد کنید.
۵. «ذخیره تنظیمات» و سپس «پایان تنظیمات و شروع چرخه» را بزنید.
۶. در داشبورد همان توکن را وارد کنید تا داده‌های دریافتی دیده شوند.

رمز و توکن خالی در فرم، مقادیر قبلی را حفظ می‌کنند؛ برای حذف از گزینه پاک‌کردن استفاده کنید.
تنظیمات خوانده‌شده از برد رمز یا توکن را برنمی‌گردانند. اپ این دو مقدار را روی دیسک ذخیره نمی‌کند.

## رفتار دستگاه

- هر روشن‌شدن، ریست یا بیداری با SW1: یک نمونه آزمایشی و پنجره BLE حداکثر ۱۸۰ ثانیه.
- بیداری زمان‌بندی‌شده: نمونه‌برداری بدون روشن‌کردن BLE.
- پیش‌فرض: نمونه‌برداری هر ۹۰۰ ثانیه و ارسال هر یک نمونه. بازه مجاز ۶۰ تا ۸۶۴۰۰ ثانیه و ارسال هر ۱ تا ۳۲ نمونه است.
- Wi-Fi فقط در نوبت ارسال فعال می‌شود؛ اتصال، زمان و TLS مجموعاً بودجه سخت ۴۵ ثانیه دارند.
- موفقیت HTTP از خانواده 2xx، صف را پاک می‌کند. خطا صف را حفظ می‌کند و تلاش بعدی در نوبت ارسال بعدی است.
- حداکثر ۳۲ نمونه در RTC RAM حفظ می‌شوند. با پرشدن صف، قدیمی‌ترین نمونه حذف و شمارنده ازدست‌رفته زیاد می‌شود. قطع تغذیه، نمونه‌های ارسال‌نشده را پاک می‌کند.
- زمان واقعی بعد از اتصال SNTP از طریق RTC بین خواب‌ها حفظ می‌شود. نمونه پیش از همگام‌سازی `timestamp: null` دارد؛ زمان دریافت سرور جداست.
- رله‌ها و فعال‌ساز RS485 هنگام خواب پایین/خاموش نگه داشته می‌شوند.
- BLE در Deep Sleep قابل کشف نیست. با SW1 روی GPIO34 دستگاه را بیدار کنید. اگر دکمه هنگام ورود به خواب پایین مانده باشد، بیداری دکمه برای همان چرخه غیرفعال می‌شود تا حلقه بیدارشدن ایجاد نشود؛ تایمر فعال می‌ماند.

## وضعیت بررسی

- Android: ساخت Debug APK و Android Lint روی سیستم فعلی موفق بوده‌اند؛ warningهای باقی‌مانده شامل منابع قالب، ترجمه رشته‌ها و نسخه وابستگی‌ها هستند.
- Server: هشت آزمون یکپارچه HTTP برای احراز هویت، اعتبارسنجی، ذخیره، ثبت تکراری و ورودی نامعتبر پاس شده‌اند.
- Firmware: کد بر اساس APIهای ESP-IDF 5.5 نوشته شده؛ ESP-IDF و toolchain در محیط فعلی پیدا نشده‌اند و ساخت یا فلش آن هنوز تأیید نشده است.
- ارتباط BLE با گوشی واقعی، ارسال واقعی از برد و جریان مصرف سخت‌افزار هنوز اندازه‌گیری نشده‌اند.

## محدودیت سخت‌افزار فعلی

مدار فعلی شامل ورودی ۲۴ ولت، مبدل ۵ ولت، LD1117-33، LED پاور، رابط USB و تجهیزات جانبی است.
باتری موجود در بخش RTC برای پشتیبان ساعت است؛ مدار شارژ و اندازه‌گیری باتری ۴۰۰mAh برای تغذیه کل دستگاه در این طرح مشخص نشده است.
این برد برای توسعه نسخه اول استفاده می‌شود؛ عمر چندماهه باتری را نمی‌توان با آن تأیید کرد. جزئیات در [یادداشت سخت‌افزار](docs/hardware-v1.md) آمده است.

به‌روزرسانی OTA، سنسور واقعی، درصد باتری، صف ماندگار در قطع برق و رمزنگاری NVS/Secure Boot در این نسخه پیاده نشده‌اند.
